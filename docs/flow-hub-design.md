# 标签页与工作线索中枢：设计草案

状态：方案，不代表已实现收藏自动化、AI 分类、分批恢复或清理 Agent。0.6.1 实现保存位置配置、临时目录随档案迁移、默认导出位置与运行目录展示。

## 浏览器整窗收藏作为补充采集

Edge 官方操作名为 `favorite_all_tabs`，快捷键 Ctrl+Shift+D。它是可配置快捷键的浏览器操作；尚未找到微软公开支持的 `msedge.exe --favorite-all-tabs` 终端参数，不能把内部操作名当成启动参数。它针对当前窗口，不能一次覆盖所有窗口。

建议先在一个窗口试用，再决定是否作为自动化入口：

1. 暂缓普通补读及截图任务，列出本次普通浏览器窗口并记录身份、预计页数和当前前台窗口。默认排除无痕。
2. 逐个激活整个窗口，触发 Ctrl+Shift+D；通过 Windows 无障碍接口验证前台进程、窗口身份和收藏对话框。失焦、弹框不同或不响应立即暂停，不向未知窗口发送按键。
3. 在浏览器中创建唯一名称的收藏夹，例如 `AEKeeper_日期_时间_随机标识_窗口序号`，等待用户确认或经验证的保存按钮。单页窗口单独处理，快捷键可能不可用。
4. 只读该个人资料的 Bookmarks 文件，等待本次文件夹完整写入并稳定；保留浏览器、个人资料、文件夹标识、顺序、实际保存时间和采集方式，原文件只读。
5. 对照原窗口已知清单与收藏结果，分别显示预期、保存、跳过和未确认数量。重复网址可能被浏览器合并，内部页面可能跳过；数量匹配也不能证明一一对应。没有稳定标签身份时只作为独立整窗收藏档案，不按位置或标题填回当前标签，也不伪造完整每日快照。
6. 写入 D 盘事务并重新读取校验后显示结果。任何失败保留已有存档和本次收藏夹；不自动删除浏览器收藏，不自动关闭原网页。

从 Chromium 的整窗收藏实现看，它读取浏览器现有的标签标题/网址并弹出收藏对话框，因此值得先验证是否能绕过某些远程调试元数据缺失，而不逐个加载网页。这是实现思路的推断，仍需在实际 Edge 版本测试；不是冻结浏览器的解锁办法，也不能保证所有页可读。

参考：[微软 Edge 操作名](https://learn.microsoft.com/en-us/deployedge/edge-learnmore-configurable-edge-commands)、[官方快捷键](https://support.microsoft.com/en-us/edge/keyboard-shortcuts-in-microsoft-edge)、[Chromium 整窗收藏入口](https://chromium.googlesource.com/chromium/src.git/+/refs/heads/main/chrome/browser/ui/browser_commands.cc)。

## 让线索留着，让暂时不用的页面退出活跃工作区

保留两个平行视图：按日期回顾当时现场；按项目/主题跨日期汇总。同一网址的内容索引可去重，每次出现在哪天、哪个窗口、什么顺序和备注仍分别保存。原始日期档案不可被 AI 整理结果替换。

建议交互：一组网页形成一个“工作包”，显示主题、原始窗口、最近活动、下一步、恢复入口和可选回顾日期。每个工作包由用户选一个状态：

- 正在做：保留当前上下文，在前台工作区容易找到。
- 等待继续：写一句“做到哪里、下次先做什么”，可指定回顾日期。
- 资料留存：可以检索，保留原日期和来源，不需要持续占据浏览器窗口。
- 需要确认：AI 不确定或信息不足，等待用户决定。

重要性、紧急性、是否当前要做分开标记；旧、少访问或重复不等于无用。AI 提供分类和理由、相关项目及下一步草稿，不自行判定丢弃。人工修改覆盖 AI 建议，分组可撤销。首次接入外部模型前说明要发送的标题、网址或可选摘录，并由用户选择模型与发送范围；默认不发送截图、登录信息或表单。

收藏和分类本身不释放原标签的内存。第一阶段依靠浏览器原生休眠减少活跃资源；要进一步释放，只能在可靠存档后，由用户选择关闭或卸载哪些页面。AI 不自动关闭。含未提交表单、编辑器、上传、付款或运行中任务的页需人工检查，网址和截图不能恢复这些内存状态。

恢复默认只展开工作包清单，由用户选当前要继续的窗口与少量页面；后续加入可暂停的队列和资源门限，不一次恢复全部历史窗口。保留“恢复整个窗口”的手动选择，并提示大量页面会重新占用资源。

参考：[Edge 休眠标签说明](https://support.microsoft.com/en-us/edge/learn-about-performance-features-in-microsoft-edge)。

## 存放与清理边界

档案、截图、SQLite 临时文件、索引、导出、备份和产品运行日志统一跟随所选磁盘。配置磁盘不可用时明确报错，不自动转到 C 盘创建空档案。打包单文件启动器需在程序解包前设置 TEMP/TMP；仅在 Python 内设置临时目录不能阻止启动解包先占用系统盘。

后续清理 Agent 单独实现：先定时扫描，生成路径、占用、用途、应用是否正在使用的清理候选。只对已确认的可重建缓存按明确规则处理；下载、项目、浏览器资料、数据库、备份、模型文件和来源不明目录不凭 AI 猜测删除。AI 用来解释和归类，文件访问规则及清理清单负责约束实际执行。当前版本不创建任何定时清理任务。
