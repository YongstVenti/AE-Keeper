# 高清画面和档案存储

没有一个格式在所有画面、清晰度和保存速度上都最优。0.5.0 根据用途选择：

| 数据 | 保存方式 | 目的 |
|---|---|---|
| 窗口缩略图 | 比较有界无损与有损 WebP，保留较小者，长边可选 320/480/640 | 卡片快速预览 |
| 高清：无损清晰 | 无损 WebP，长边可选 1280/1920/2560/3840 | 保留采集尺寸下的文字像素 |
| 高清：节省空间 | 比较无损 WebP、WebP 85 和 AVIF 80（4:4:4），保留编码后最小者 | 允许轻微有损，减少照片等画面的空间 |
| 浏览器及工作现场快照 | Zstandard level 9，无损压缩 JSON 元数据 | 标题、链接和窗口信息不丢失 |
| 共享内容 | SHA-256 内容寻址的 SQLite BLOB | 相同图片、相同快照跨日期或副本仅存一份 |
| 日期、备注、访问记录与书签 | SQLite 结构化数据 | 保留检索能力，不为压缩破坏索引 |

图片直接保存为二进制对象，数据库中不保存重复的 Base64 文本。快照只引用对象；每日主存档、子快照各自保留时间和备注。清理时只删除不再被任何快照引用的对象。工作现场容量按共享对象实际编码大小计算，未引用对象不计入，也不会累积。SQLite 使用增量回收闲置页；容量统计是内容及记录开销，不等于整个数据库、WAL 和升级安全备份的文件总大小。

手动高清采集使用 DWM 源画面尺寸及分块投影，必要时拼接，源窗口保持原最小化状态。编码只缩小到上限，不放大小图。自动采集不弹出预览板；无法读取的窗口沿用同一窗口上次的画面，显示原截图时间。高清默认关闭。开启高清增加信息量，不能保证同时得到无限清晰度和最小文件；单张高清图限制 8 MB，超限会保留缩略图并说明原因。

## 可复现的合成样本结果

本机 Pillow 12 / Zstandard 0.25，1920×1080、30 行重复文字和浅色界面，单次编码结果：

在仓库根目录运行 `python tools/benchmark_storage.py` 可复测合成样本，不读取用户内容。

| 格式 | 大小 | 编码用时 | 与输入像素完全一致 |
|---|---:|---:|---|
| PNG optimize | 320,077 B | 0.159 秒 | 是 |
| WebP 无损 | 15,262 B | 0.088 秒 | 是 |
| WebP 85 | 144,890 B | 0.155 秒 | 否 |
| AVIF 80，4:4:4 | 132,502 B | 0.153 秒 | 否 |

该样本无损 WebP 比 PNG 小约 95%，也比有损格式更小。131 个合成标签页的 JSON 为 19,460 B，zlib 9 为 1,283 B，Zstandard 9 为 879 B。结果只代表这一合成样本；照片、噪声、字体和硬件会改变结果。编码时间包含 Python 调用，不代表各库的通用性能。

原生采集另外验证：2000 像素宽的自建合成窗口最小化后，仍采集到 1920×1086 的高清图；源窗口没有展开。此验证不使用用户内容。

## 升级和备份

第一次压缩旧档案前，先保存并校验 `archive-before-compact-*.sqlite3`。旧记录转换在事务中进行，日期、主存档关系、备注和图片保留。转换后整理数据库空页；安全备份保留原文件占用，确认新档案正常前请保留。

JSON 导出会展开所有对象为自包含备份，继续兼容原导入格式。因此导出的备份可能比内部档案大。旧版本不能直接读写新版内部格式；回退应还原升级前数据库。私有图片、数据库和备份不进入开源仓库。

参考开源实现与官方文档：[libwebp 编码选项](https://developers.google.com/speed/webp/docs/cwebp)、[libavif](https://github.com/AOMediaCodec/libavif)、[Zstandard](https://facebook.github.io/zstd/)、[SQLite 应用文件格式](https://sqlite.org/appfileformat.html)。这些依赖沿用各自的开源许可证。
